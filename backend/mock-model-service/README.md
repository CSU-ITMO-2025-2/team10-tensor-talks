## mock-model-service — заглушка модели для обработки чатов

`mock-model-service` — это умная заглушка, которая имитирует работу AI-модели для обработки чатов. Сервис читает события из Kafka (`chat.events.out`) и отправляет ответы в Kafka (`chat.events.in`).

## Логика работы

### Порядок обработки событий

1. **Событие `chat.started`:**
   - Создаёт состояние сессии
   - Отправляет первый вопрос через `chat.model_question`
   - Увеличивает счётчик вопросов до 1

2. **Событие `chat.user_message`:**
   - Проверяет количество заданных вопросов
   - Если `questions_asked >= max_questions` (5) → отправляет `chat.completed` с результатами
   - Если лимит не достигнут → отправляет следующий вопрос и увеличивает счётчик

### Пример потока (max_questions = 5)

```
1. chat.started → вопрос 1 (счётчик: 1)
2. user_message → вопрос 2 (счётчик: 2)
3. user_message → вопрос 3 (счётчик: 3)
4. user_message → вопрос 4 (счётчик: 4)
5. user_message → вопрос 5 (счётчик: 5)
6. user_message → chat.completed (счётчик: 5 >= 5)
```

### Особенности

- **Правильный порядок:** Обрабатывает события в правильной последовательности (пользователь → модель → пользователь)
- **Умная логика:** Отслеживает состояние каждой сессии и количество заданных вопросов
- **Автоматическое завершение:** Завершает чат после заданного количества вопросов
- **Статичные вопросы:** Использует набор из 20 предопределённых вопросов по ML
- **Генерация результатов:** Создаёт оценку, обратную связь и рекомендации на основе количества вопросов

## Конфигурация

- `MOCK_MODEL_SERVER_HOST` — хост сервера (по умолчанию "0.0.0.0")
- `MOCK_MODEL_SERVER_PORT` — порт сервера (по умолчанию 8084)
- `MOCK_MODEL_KAFKA_BROKERS` — адреса Kafka брокеров
- `MOCK_MODEL_KAFKA_TOPIC_CHAT_OUT` — топик для чтения (chat.events.out)
- `MOCK_MODEL_KAFKA_TOPIC_CHAT_IN` — топик для записи (chat.events.in)
- `MOCK_MODEL_KAFKA_CONSUMER_GROUP` — группа consumer
- `MOCK_MODEL_MODEL_MAX_QUESTIONS` — максимальное количество вопросов (по умолчанию 5)
- `MOCK_MODEL_MODEL_QUESTION_DELAY_SECONDS` — задержка перед отправкой вопроса (по умолчанию 2)

## Вопросы

Сервис использует набор из 20 статичных вопросов по машинному обучению:
- L1/L2 регуляризация
- Кросс-валидация
- Bias-variance tradeoff
- Градиентный спуск
- Overfitting
- Метрики (precision, recall, ROC-AUC)
- Алгоритмы (SVM, Random Forest, k-means)
- Feature engineering
- PCA
- И другие...

Вопросы выбираются по индексу (с циклическим перебором) для разнообразия.

## Генерация результатов

### Оценка (Score)
- Базовая оценка: `60 + (questions_asked * 5)`
- Случайный фактор: ±10
- Диапазон: 0-100

### Обратная связь (Feedback)
Зависит от оценки:
- ≥90: "Отличное понимание основ машинного обучения..."
- ≥75: "Хорошее понимание основ ML..."
- ≥60: "Базовое понимание машинного обучения..."
- <60: "Требуется дополнительное изучение..."

### Рекомендации
Зависят от оценки:
- <70: Базовые рекомендации (линейная регрессия, метрики)
- 70-85: Продвинутые рекомендации (регуляризация, feature engineering)
- ≥85: Экспертные рекомендации (нейронные сети, ML System Design)

## Метрики

- `tensortalks_http_requests_total` — HTTP запросы
- `tensortalks_http_request_duration_seconds` — длительность HTTP запросов

## Логирование

Все операции логируются:
- Создание сессий
- Получение событий от BFF
- Отправка вопросов
- Завершение чатов
- Ошибки обработки
