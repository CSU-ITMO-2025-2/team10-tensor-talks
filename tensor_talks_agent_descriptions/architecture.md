
## 1. Общая идея архитектуры

Архитектура построена вокруг **event-driven подхода** с использованием **Kafka** как центральной шины событий и **LLM-агента**, работающего поверх **langgraph**.
Основные цели системы:

* Обработка чатов в near-real-time
* Агрегация диалогов
* Хранение полной истории сообщений
* Асинхронная генерация ответов LLM-агентом
* Постобработка / разметка (marking)
* Масштабируемость и слабая связность микросервисов

Ключевой принцип:
👉 **HTTP — только для входа и финальных API**,
👉 **вся бизнес-логика и взаимодействие — через Kafka**.

---

## 2. Границы системы

Жёлтая пунктирная рамка — **основной контур обработки чатов**.
За её пределами могут находиться:

* UI / frontend
* внешние клиенты
* сторонние сервисы

---

## 3. Точка входа — BFF (Backend For Frontend)

### BFF

**Роль:**

* Единственная HTTP-точка входа для клиента (frontend / mobile / external API)
* Инкапсулирует сложность микросервисной архитектуры
* Работает синхронно для клиента, асинхронно — внутри системы

**Функции:**

* Приём сообщений пользователя
* Запросы истории диалога
* Получение текущего состояния чата / ответа агента
* Публикация событий в Kafka

### Основные исходящие потоки из BFF:

1. **Kafka Publication topic**
2. **Kafka Messages Events**
3. Запросы к CRUD-сервисам (чтение данных)

---

## 4. Kafka Publication topic

### Назначение

Это **топик команд / публикаций**, куда BFF отправляет события вида:

* `NewUserMessage`
* `StartDialogue`
* `ContinueDialogue`
* `UserAction`

### Особенности:

* Содержит **минимальный payload**
* Используется для запуска асинхронных процессов
* Не является источником истины

### Подписчики:

* Dialogue Aggregator
* CRUD-сервисы
* Сервисы аналитики (опционально)

---

## 5. Kafka Messages Events

### Назначение

Топик **событий сообщений** (event stream):

* входящие сообщения пользователя
* системные сообщения
* промежуточные события диалога

### Отличие от Publication topic:

| Publication          | Messages Events                 |
| -------------------- | ------------------------------- |
| Командный            | Событийный                      |
| Триггерит действия   | Фиксирует факт                  |
| Может быть transient | Используется для восстановления |

### Подписчик:

* **Dialogue Aggregator**

---

## 6. Dialogue Aggregator — ключевой сервис системы

### Центральный компонент

Dialogue Aggregator — **сердце архитектуры**.

### Его задачи:

1. **Агрегация диалога**

   * Собирает сообщения из Kafka
   * Группирует по chat_id / dialogue_id

2. **Работа с состоянием**

   * Поддерживает текущее состояние диалога
   * Использует **Key-Value storage по чату**

3. **Обогащение**

   * Добавляет метаданные
   * Проставляет роли (user / assistant / system)

4. **Fan-out событий**

   * Публикует данные в разные Kafka-топики

---

## 7. Key-Value хранилище по чату

### Назначение

* Быстрый доступ к состоянию диалога
* Контекст для LLM
* Кэш последних N сообщений

### Типичные данные:

* chat_id
* dialogue_state
* last_messages
* flags (is_finished, awaiting_llm, etc.)

### Используется:

* Dialogue Aggregator
* REST API для быстрого ответа клиенту

---

## 8. Kafka Messages Full Data

### Назначение

Топик **полных сообщений** с максимальным payload:

* текст
* embeddings (если есть)
* метаданные
* timestamps
* source

### Используется:

* LLM-агентом
* аналитикой
* оффлайн-обработкой

---

## 9. Kafka Full History Events

### Назначение

**Исторический лог диалогов** — immutable event store.

### Отличия:

* Никогда не перезаписывается
* Используется для:

  * восстановления состояния
  * обучения моделей
  * аудита
  * replay

### Подписчики:

* Dialogue Aggregator
* Rest API marking service

---

## 10. CRUD сервисы и базы данных

### CRUD → ЧАТЫ

* Хранит метаинформацию о чатах
* chat_id, user_id, статус, timestamps

### CRUD → РЕЗУЛЬТАТЫ

* Хранит финальные результаты обработки
* ответы LLM
* оценки
* разметку

CRUD-сервисы:

* работают синхронно
* вызываются из BFF и marking service
* не знают о Kafka напрямую (или минимально)

---

## 11. Kafka Generated Phrase

### Назначение

Топик **сгенерированных LLM-ответов**.

### Источник:

* Rest API for Agent based on langgraph

### Payload:

* chat_id
* generated_text
* confidence / metadata
* intermediate_steps (опционально)

### Подписчик:

* Dialogue Aggregator

---

## 12. Rest API for Agent (langgraph)

### Роль

* HTTP-обёртка над LLM-агентом
* Использует **langgraph** для:

  * цепочек рассуждений
  * branching
  * tool-calling

### Вход:

* данные из Kafka Messages Full Data

### Выход:

* публикация в Kafka Generated Phrase

### Почему REST:

* изоляция LLM
* удобство масштабирования
* независимость от Kafka-консьюмеров

---

## 13. Rest API Marking Service

### Назначение

Сервис **постобработки и разметки**.

### Вход:

* Kafka Full History Events

### Функции:

* классификация диалогов
* оценка качества ответа
* модерация
* тегирование

### Выход:

* запись результатов в CRUD → РЕЗУЛЬТАТЫ

---

## 14. Полный жизненный цикл сообщения

1. Пользователь → **BFF**
2. BFF:

   * пишет в Kafka Publication topic
   * пишет в Kafka Messages Events
3. Dialogue Aggregator:

   * обновляет состояние чата
   * пишет в KV-store
   * публикует в Full Data / Full History
4. LLM Agent:

   * читает Full Data
   * генерирует ответ
   * пишет в Kafka Generated Phrase
5. Dialogue Aggregator:

   * добавляет ответ в диалог
   * обновляет состояние
6. Marking Service:

   * анализирует историю
   * пишет результаты в БД
7. BFF:

   * читает агрегированное состояние
   * возвращает клиенту
